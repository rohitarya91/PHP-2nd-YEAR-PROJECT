==================================================
3. BACKEND ARCHITECTURE 
==================================================

Is project ka backend helper-based architecture follow karta hai.

Meaning:
- Har page me alag alag SQL aur session logic likhne ke bajay,
  shared backend logic `config/store.php` me rakha gaya hai.

To page files ka main kaam hota hai:
1. helper include karna
2. login/access check karna
3. required helper function call karna
4. result ko HTML me dikhana

Yeh approach better hai kyunki:
- code repeat nahi hota
- logic ek jagah central rehta hai
- maintenance easy hoti hai

==================================================
5. SESSION HANDLING
==================================================

Session `config/store.php` me start hota hai:
- `session_start()`
- aur yeh tabhi chalta hai jab session already active na ho

Main session values:
- `user_id`
- `user_name`
- `email`
- `role`
- `cart`
- `flash`

Inka meaning:
- `user_id`
  current logged-in user ko identify karta hai
- `user_name`
  dashboard me naam dikhane ke kaam aata hai
- `email`
  identity aur display ke kaam aata hai
- `role`
  admin hai ya user, yeh batata hai
- `cart`
  cart items session me store karta hai
- `flash`
  one-time success/error message ke liye

Example:
- user login karta hai
- session me `user_id`, `user_name`, `email`, `role` save ho jata hai
- fir next page par project ko turant pata hota hai ki kaun login hai

8. ROLE-BASED ACCESS CONTROL
==================================================

Ab project role-based auth use karta hai.

Main helpers:
- `require_login()`
- `is_admin()`
- `require_admin()`
- `current_user_role()`

Kaise kaam karta hai:
- `require_login()`
  guest ko protected page par jane se rokta hai
- `is_admin()`
  check karta hai session role admin hai ya nahi
- `require_admin()`
  sirf admin ko admin pages me jane deta hai

Login ke time session me store hota hai:
- `$_SESSION['role']`

Register ke time default role save hota hai:
- `user`

Schema helper existing admin ko auto sync karta hai:
- `admin@gmail.com` ko `admin` role milta hai

Yeh pehle wale hardcoded email check se better hai kyunki:
- scalable hai
- clean architecture hai
- future me aur roles add kar sakte ho
